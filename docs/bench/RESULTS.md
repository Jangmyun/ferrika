## Setup

- Machine: AMD Ryzen 5 5600X 6-Core Processor, 31.9 GiB RAM, Windows-10-10.0.19045-SP0; WSL2 VM with 15.6 GiB.
- Kafka 4.3.1 (one KRaft broker), Kafbat UI v1.5.0, AKHQ 0.28.0, Redpanda Console v3.12.0 and Kafdrop 4.3.0 in Docker on WSL2 with default settings, from [`tools/bench/compose.yml`](../../tools/bench/compose.yml).
- Ferrika 0.1.0 in two places:
  - **same network**: a Linux release build (rustc 1.99.0 (b940084d7 2026-09-28)) in a container on the broker's Docker network, the position the web servers have.
  - **from Windows**: Windows desktop build's executable in CLI mode (same engine as `ferrika`; measured 2026-10-13, not re-measured with the CLI binary) reaching the broker through WSL2's port forwarding, like a client on another machine.
- Data: topic `bench-10m`, 3 partitions, 10,000,001 JSON records (3,017.1 MiB) from `ferrika generate`. The record searched for is the last one written, at the end of its partition.

## How to read it

- **Compare the web servers with the "same network" column.** The "from Windows" column adds WSL2's port forwarding, which slows Ferrika's reads here; it stands for a client on another machine.
- Before 2026-10-13 Ferrika needed about 54 s for this search, on either network. librdkafka's `fetch.queue.backoff.ms` (default 1000 ms) paused a partition's fetching for a second each time its local queue filled, which happens over and over when a reader processes records a little slower than they arrive. Ferrika's consumers now set it to 10 ms; memory stayed the same. AKHQ's Java consumer has no such pause and takes up to 25,000 records per `poll()`.
- Later that day Ferrika's searches and `bench consume` moved to one consumer per partition (up to 8), each on its own thread and filtering there, instead of one consumer for the topic. One librdkafka consumer reads a broker through one connection and one thread; with three the search took 6.6 s → 3.1 s on the same network and 12.3 s → 5.1 s from Windows. Each consumer's prefetch queue is capped at 8 MiB (`queued.max.messages.kbytes`), which kept the peak memory below the single consumer's.
- The "same network" Ferrika runs in a container inside the WSL2 VM, sharing its CPUs with the broker and the web servers, as they share them with each other.
- Server memory is the container only (usage minus inactive page cache, as `docker stats` shows it). Each user's browser tab comes on top. Ferrika memory is the whole process (max RSS on Linux, working set on Windows).
- Search: Kafbat UI `messages/v2` with `stringFilter` (key or value contains); AKHQ `data/search` with `searchByValue`; Redpanda Console `ListMessages` with the JavaScript filter `return value.order_id == "…"` (its way to search); Kafdrop's search page, which gives up after a fixed number of scanned records (see `scanned_before_stopping` in results.json) and so cannot find this record; Ferrika `consume -b -G` (case-insensitive regex over the value), stopping at the first match. - Start: the web servers from container start until the topic list API answers. The CLI has no server to start, so it has no entry.
- Topic list: the web servers answer one API call while already connected; the Ferrika time is a whole CLI run that starts a process and connects.
- Redpanda Console is a Go server; the others are JVM servers. The JVM servers run with their default heap limit (a quarter of the WSL2 VM's memory). Their memory reflects how far the heap grows when allowed; a smaller `-Xmx` caps memory but may slow or fail large searches. That trade-off was not measured.
- Scope: one machine, one 3 GiB topic, one scenario family (finding a single record, plus a plain read), default settings for every product, and the versions listed above. A web UI and a command line do different jobs; these numbers compare how long and how much memory it takes to find one record, not features, and other topologies or settings can give other results.

Reproduce: `docker compose -f tools/bench/compose.yml up -d`, set up the Linux build container (see the docstring of `run.py`), then `python tools/bench/run.py prepare` and `python tools/bench/run.py measure`.
